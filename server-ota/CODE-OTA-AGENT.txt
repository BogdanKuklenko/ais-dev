Обновление КОДА пульта — точечный патч, не весь exe

Источник правды: ветка main. После каждого push GitHub Actions делает `npm run build`,
скрипт scripts/publish-ota-dist.cjs сам публикует ветку ota-dist (code-patch.json + файлы UI).
Это не нужно делать руками и не зависит от правки YAML workflow.

Клиент
- Сравнивает gitSha опубликованного патча с overlay-info (не «случайные» совпадения хешей).
- Сборка с gitSha local/unknown всегда предлагает скачать интерфейс с GitHub.
- Установка качает ВСЕ файлы манифеста (~1–2 МБ), проверяет SHA-256, кладёт в userData/app-overlay.
- Центр обновлений при открытии сам проверяет патч.

Манифест
https://raw.githubusercontent.com/BogdanKuklenko/ais-dev/ota-dist/code-patch.json
format: alex_code_patch_v1

Что делать агенту при изменении окон, текстов, логики React/Vite
1. Меняй исходники как нужно.
2. Пушь ВЕСЬ нужный UI в main (не только updater).
3. НЕ собирай exe. НЕ выкладывай на Cloud Run. НЕ правь update-manifest.json ради UI.
4. Actions сам опубликует ota-dist.
5. На заводе: новый пульт один раз (ядро с overlay). Дальше Центр обновлений → патч качается сам.

Когда НУЖЕН полный exe (ядро Electron)
- Правки electron-*.cjs, смена Electron, первый заводской экземпляр без overlay.
- Release tag latest-win.

Нельзя
- Cloud Run / alex-mixes.ru
- Ручная ветка ota-dist, если CI уже публикует её из npm run build
- Частичный пуш UI (иначе GitHub и пульт снова разъедутся)

Рецептуры
Отдельный JSON public/update-manifest.json. bump latestVersion + новый patchId.
